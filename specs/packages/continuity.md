# continuity: 业务数据延续与升级

## 意图

本包依据 [DR-003](../decisions/003-enrollment-data-continuity.md) 定义本地业务数据的提交、升级、重启与备份恢复保证。
本包负责存储成功语义，不重新定义报名资格、课程发布或账号权限。

## 外部行为

### continuity-1

当业务状态写入被报告为成功，持久化服务应已将结果提交至当前数据目录的本地 SQLite 数据库，正常停服重启后保持成功结果，提交失败时不报告成功或保留部分写入。

### continuity-2

当升级已有数据库以支持报名，迁移流程应保留原账号编号、用户名、显示名、角色、密码凭据及课程编号、内容、视频关联、发布状态和已有时间信息，不清空数据、不重置示例数据，也不为原有学员自动生成报名。

### continuity-3

当服务启动或执行数据库迁移，数据管理服务应沿用增量编号迁移规则：

- 全新数据库启动时执行全部迁移并初始化一次示例账号和课程。
- 已有数据库存在待执行迁移时拒绝启动并提示先备份、迁移，再启动。
- 已执行迁移被修改、删除或追加文件排在已执行编号之前时拒绝迁移和启动。
- 新结构只追加更大编号的迁移，每个迁移文件原子执行，失败文件回滚，先前成功文件保留。
- 重复迁移无待执行项时不改变业务数据。

### continuity-4

当账号退出后重新登录或服务正常重启，业务系统应维持原账号的报名有效性 [[enrollment-6](enrollment.md#enrollment-6)]与本人列表 [[enrollment-7](enrollment.md#enrollment-7)]，使已成功报名仍有效、已成功取消仍无效，登录会话变化不转移报名归属。

### continuity-5

当执行备份、恢复或迁移维护，数据管理服务应保留既有维护边界并覆盖报名数据：

- 同一数据目录只允许一个服务或维护任务占用，失效进程的运行记录可清理。
- 备份正常停止运行中的服务，检查数据库完整性后保存不覆盖旧文件的快照，服务保持停止。
- 迁移和恢复要求服务停止。
- 恢复先校验快照并保存恢复前副本，无效快照不替换当前数据。
- 恢复包含该快照时点的账号、课程和报名状态，不包含快照之后的操作；旧快照的待执行迁移仍需补齐。

### continuity-6

当在受支持环境运行项目，运行环境应只需要 Node.js 24，无 npm 依赖安装、构建步骤或运行时联网，沿用 DATA_DIR、PORT、BACKUP_DIR 配置及本机监听行为，不将数据库、data 或 backups 纳入版本控制。

## 验证

### continuity-7

给定真实服务和隔离数据目录，当集成测试写入业务状态、正常重启并在受控写入失败条件下再次提交，测试应断言成功结果保留、失败不返回成功且无部分写入 [[continuity-1](#continuity-1)]。

### continuity-8

给定包含修改过的示例数据、自建课程及既有登录凭据的旧数据库副本，当系统测试完成备份、迁移和启动，测试应断言升级前后原业务字段一致、旧凭据仍可登录、无重复示例数据且报名为空 [[continuity-2](#continuity-2)]。

### continuity-9

给定全新和旧数据库副本，当系统测试分别启动、追加迁移、重复迁移、制造迁移失败及篡改已执行迁移，测试应断言初始化一次、待迁移拒启、单文件回滚和不一致记录拒绝执行 [[continuity-3](#continuity-3)]。

### continuity-10

给定两个真实学员分别完成报名和取消，当系统测试退出重登、切换账号及正常重启后查询列表并申请观看，测试应断言报名状态和归属延续且已取消记录不恢复 [[continuity-4](#continuity-4)]。

### continuity-11

给定包含有效与已取消报名的数据库快照，当系统测试备份、产生后续报名变化并恢复快照，测试应断言快照状态恢复、后续变化不保留、恢复前副本存在，并验证并发占用、运行中维护及无效快照被拒绝 [[continuity-5](#continuity-5)]。

### continuity-12

给定 Node.js 24 和隔离目录，当系统测试在禁止外网条件下直接执行 npm start 并使用不同数据目录与端口，测试应断言服务可运行、数据隔离、无需安装构建且仓库不跟踪运行数据 [[continuity-6](#continuity-6)]。
