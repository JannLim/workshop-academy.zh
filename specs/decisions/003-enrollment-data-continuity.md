# DR-003: 报名持久化与既有数据延续

## 状态

已接受（2026-11-11）

## 背景

- 项目已有账号、课程和本地 SQLite 数据库，不能通过重建数据库增加报名功能。
- 学员需要在退出登录或服务重启后继续查看、管理和使用自己的报名。
- 现有数据库通过编号迁移增量演进，已有数据库存在待执行迁移时拒绝直接启动。

## 决策

### 数据延续保证

- 升级报名功能时保留已有账号及登录凭据、课程内容与发布状态，不重置已有数据或重复写入示例数据。
- [DR-001](001-self-service-enrollment.md) 定义的报名和取消操作只有在结果持久化后才报告成功，正常重启后维持成功操作的结果。
- 报名归属于账号和课程，不依赖某次登录会话，退出后重新登录仍可查看和管理。
- 取消成功的报名在重启后不会恢复为有效报名。
- 不为既有学员自动补报课程，既有学员也需主动报名后才能按 [DR-002](002-enrollment-watch-eligibility.md) 获得观看资格。

### 升级与运行约束

- 沿用项目现有本地 SQLite 持久化与编号迁移机制，仅追加新迁移，不修改已执行迁移，不以删库重建方式升级。
- 已有数据库沿用“备份 → 迁移 → 启动”的升级流程；全新数据库沿用首次启动建库和初始化流程。
- 报名数据纳入同一数据库的备份和恢复范围，恢复快照只保证保留该快照时点的数据。
- 保持只依赖 Node.js 24、无新增 npm 依赖、无构建步骤及运行时不联网的项目约束。
- 本决策不规定报名表结构、字段、索引或取消历史的具体存储方式。

## 影响

- 升级需安排现有流程要求的停服、备份和迁移，不能通过直接启动跳过待执行迁移。
- 保留既有数据不等于保留“登录即可观看”的权限，原学员需完成一次主动报名。
- 可使用已有账号和课程的数据库副本验证升级前后的数据一致性，再通过报名、取消、退出重登与服务重启验证状态延续。
- 备份恢复验证需覆盖报名数据，但不承诺恢复快照之后产生的操作结果。
